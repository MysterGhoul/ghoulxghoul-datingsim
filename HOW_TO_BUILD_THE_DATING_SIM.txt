HOW WE BUILD / UPDATE THE DATING SIM
=====================================
Live at: https://dating.ghoulxghoul.com   (once the DNS record below is added)
Until then: https://mysterghoul.github.io/ghoulxghoul-datingsim/

WHAT IT IS
- "Mission: GhoulxGhoul Gets Laid" - a browser dating sim.
- Code: index.html (all CSS inline) + game.js (Day 1 + shared engine) + day2.js (Day 2
  content + flow) + walk.js (Mochi's Walk pixel mini game). No build step, no framework.
- Everything else is in assets/.

HOSTING
- GitHub Pages, repo MysterGhoul/ghoulxghoul-datingsim, branch main, /root.
- Custom domain will be dating.ghoulxghoul.com via a CNAME file.
- DNS is at Squarespace (same place as the lore site).
- Push = auto-deploy (git credential manager handles auth).

⚠ WHY NOT ghoulxghoul.com/datingsim
- ghoulxghoul.com is served by Fourthwall (the merch platform). We cannot drop a
  multi-file JS game at a path there. Same reason the lore site lives at
  lore.ghoulxghoul.com. Subdomain is the pattern for anything we build ourselves.

TO FINISH THE CUSTOM DOMAIN (one-time, needs a human)
1. Squarespace DNS for ghoulxghoul.com -> add a record:
      Type: CNAME     Host: dating     Value: mysterghoul.github.io
2. Then here:
      cd "C:\Users\MysterGhoul\Documents\GhoulxGhoulGame"
      mv CNAME.pending CNAME
      git add CNAME && git commit -m "custom domain" && git push
3. GitHub repo -> Settings -> Pages -> Custom domain -> dating.ghoulxghoul.com,
   then tick "Enforce HTTPS" once the cert issues (can take ~15 min).
   (The CNAME file is held back until DNS exists, because with it committed the
   github.io URL 301-redirects to a domain that would not resolve yet.)

TO EDIT + DEPLOY (the whole loop)
1. Edit index.html / game.js / assets
2. Test locally FIRST - you cannot open index.html directly, browsers block it:
      cd "C:\Users\MysterGhoul\Documents\GhoulxGhoulGame" && python -m http.server 8777
      -> http://127.0.0.1:8777
3. git commit -am "what changed"
4. git push
5. Wait ~60-120s, hard-refresh, confirm.

THE TWO DAYS
- Day 1: intro -> 2:00 hunt (3 rooms, 5 items) -> stream clip -> sushi date -> 70% wins.
  Winning Day 1 shows "DAY 2 UNLOCKED" + Continue (and sets localStorage gxg_day2=1, which
  adds a "Skip to Day 2" button on the title so nobody has to replay the date to test Day 2).
- Day 2 (day off, its own 100-point bar, 70% to win): wake-up dialogue (10) -> Mochi's Walk
  (32, speed-scaled: 25 pts inside 75s = full) -> second hunt, same rooms, lotion / baby oil /
  riding crop / ball gag (58). Finding an item FREEZES the hunt clock and opens a "what's the
  plan" dialogue; Day 1 rules (best / good / heart-loss, one trap: the door hinge).
  Every Day 2 failure = Try Again (restarts Day 2) / Give Up (title). Day 2 win = the real
  finale: sting -> "You win, big boy." -> Yamete -> YOU WIN + confetti.
- MOBILE: works in landscape (portrait shows a "turn your phone" prompt). Day 1 and the hunts
  are taps. Mochi's Walk has touch controls: hold a finger and the couple walks toward it
  (held ~90px above the finger so it isn't covered), and a JUMP button bottom-right. The
  button appears on any coarse-pointer device or on the first real touch. Text gets small on
  a phone but stays readable; hunt items are the fiddliest thing to tap.
- ?day2 in the URL unlocks the "Skip to Day 2" title button without winning Day 1.
- Mochi's Walk: WASD/arrows move the couple, SPACE jumps the whole party (airborne you clear
  sewer holes but can't grab balls). Tennis ball +1, hydrant +3 (everyone waits 2s while Mochi
  pees), open sewer -1 (floors at 0). 3:00 clock, 25 to clear. Knobs at the top of walk.js:
  NEED, LIMIT, SCROLL, MOVE, spawn timers in fresh(). Sprites are pixel-map strings (PAL = palette).
  The dog is drawn from behind so glasses read as the arms at the temples; the front-facing
  portraits in the HUD are where the glasses + mustache actually show.
- The hunt engine is config-driven: startHunt(HUNT_D1 | HUNT_D2). A config = rooms, items,
  intro line, onFound(id, left), onDone, onTimeUp. pauseHunt()/resumeHunt() freeze the clock.

WHERE THE CONTENT LIVES (plain data at the top of game.js / day2.js)
- INTRO              the opening question
- ITEMS / DECOYS     what to find, and the joke items
- ROOMS              which room holds what, x/y are % of the screen
- NARR               cutscene narration, [ms, "line"]
- ROLLS              the sushi menu
- DATE               every question on the date
- MUSIC / SFXFILE    audio paths
- WAKE / AFTER_WALK / D2_DLG / ROOMS_D2 / ITEMS_D2   (day2.js) everything Day 2 says and hides

A dialog option:
  { t: `What you say`, p: 4, fx: ['SMOOTH','good'], mood: 'happy', r: `What she says back` }
  p = points | h:1 costs a heart | end:'...' is an instant Game Over
  mood picks the photo | fx is the flash word (great gold / good green / meh grey / bad red)
  MAX recalculates itself, so add or remove questions freely.

TUNING KNOBS
- GOAL        70    % of the rizz meter needed to win
- HUNT_LIMIT  120   seconds on the hunt clock
- HUNT_FULL   40    finish inside this for full hunt marks
- MUS_VOL     0.16  background music level

SPRITES
- assets/jasmine/{stream,date}_{neutral,happy,annoyed,flirty}.png  + stream_sleepy
  stream_* = white shirt (intro + cutscene). date_* = black dress (the date).
- Shipped as .webp (10x smaller). The code tries .webp then falls back to .png,
  so you can drop in a .png replacement with the same name and it just works.
- Cut out of the white-backdrop shoot with `rembg` (pip install rembg).
  To redo one:
    python -c "from rembg import remove,new_session; from PIL import Image; \
      im=Image.open('SRC.jpg'); im.thumbnail((1200,1600)); \
      o=remove(im,session=new_session('u2net'),alpha_matting=True); \
      o.crop(o.getbbox()).save('out.webp','WEBP',quality=82,method=6)"

AUDIO
- 5 music loops (title, pre-stream/hunt, sushi, wake, walk), crossfaded.
- _music_options/day2.html has the alternates for the two Day 2 tracks. Each is a true seamless loop (tail
  crossfaded into the head) so it does not click on repeat.
- Browsers refuse audio before a real gesture, so the title track starts on the
  first click or keypress. That is a browser rule, not a bug.
- _music_options/ is the audition page used to pick tracks. It is gitignored -
  it is a workbench, not part of the site.
